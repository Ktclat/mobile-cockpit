## Root cause

The prior helper captured descendants only once, immediately after `afterStart`. In the ordinary timeout path that snapshot occurred before the PowerShell wrapper created its child, so cleanup retained only the wrapper handle. Once the wrapper died, the detached child could no longer be rediscovered through the parent.

The interruption path did capture the wrapper and child, but Windows could keep the inherited redirected-output handle locked briefly after `ProcessHandle.onExit` completed. A one-shot deletion therefore raced final operating-system handle release. The failed output files were unlocked shortly afterward, confirming a release race rather than a permanently live matching process.
